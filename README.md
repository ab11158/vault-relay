# Vault Relay 5.2.12 TEST

Obsidian 的 Windows／Android／iPadOS 增量 ZIP 与 ACK 插件。插件 ID 保持 `vault-relay-v4`，最低 Obsidian 1.5.0。本版统一百度网页目录设置，保留原平台文件运输机制。

## 安装

通过 BRAT 添加 `ab11158/vault-relay`，已有安装检查更新并核对 5.2.12；固定版本时选择 5.2.12。也可从 [GitHub Release](https://github.com/ab11158/vault-relay/releases/tag/5.2.12) 下载插件 ZIP；包内只有 `vault-relay-v4/main.js`、`manifest.json`、`styles.css`。

手动更新时仅替换同一插件目录中的这三个文件，保留原 `data.json`。不要把其他设备的身份或配置复制过来。首次使用建议测试库；正式笔记的新增、覆盖和删除仍需人工审核确认。

## 百度网盘同步空间共享目录

进入「设置与连接检查 → ① 公共设置 → 百度网盘连接」。公共设置中只有一个目录编辑区，名称为「百度网盘同步空间共享目录」。

1. 在「配置来源」选择本版已保存、旧同步空间、旧上传配置或手动新填。选择或编辑只是草稿，不改变现有按钮；两份旧配置同时存在时会显示提示。
2. 选择「同步空间」或「普通网盘」。同步空间只需输入网页可见目录，例如 `/示例目录/共享区`；插件内部处理 `/_pcs_.workspace`，历史完整路径也支持且不重复补齐。普通网盘使用原路径。
3. 可粘贴官方 HTTPS 目录网址，输入结束后查看识别结果。分享链接请填独立的「百度网盘群组长期分享链接」，不能当目录网址。官方 main 上传网址若携带完整 workspace 路径，会识别为同步空间。
4. 点击「保存百度网盘同步空间共享目录」后，浏览与上传才统一使用所选目录。保存失败保留旧值。旧 `syncSpaceTarget` 与 `ackUploadTarget` 原值保留，不自动迁移、删除或猜测其类型。
5. 「浏览目录」在同步空间打开 `/disk/synchronization`；「上传原 ZIP / ACK」打开 `/disk/main`，携带同一完整 workspace 路径。普通网盘两种操作均使用 main 页面及原路径。

升级后尚未明确保存本版目录时，上传继续使用当前群组的旧上传路径（没有则打开首页），浏览继续使用合法且匹配群组的旧同步空间配置。即使两者不同，也不会静默更改安卓已使用的上传位置。仅有旧上传配置时需自行确认类型；不要根据文件夹名称猜测。

Windows 本地目录仍在专用设置，标签为「Windows 专用 · Windows 百度网盘已同步的本地文件夹」。公共网页目录不改变本地绑定或自动运输开关，也不建立云端与本地的同步关系。

## 文件传递与保护

保留 Android 扫描、系统分享、文件选择和接收；iPadOS／iOS 使用系统“文件”选择 ZIP／ACK。保留原 ZIP／ACK 复核与导出、群组分享页下载及 Windows 保存分享链接功能。导出时保持完整原名和字节，不解压重打包。

网页由系统浏览器接口打开。导航不携带原文件，不等于上传、下载或对端接收成功；插件没有独立内置浏览器，也不承诺自动唤起百度 App。实际网页上传、Windows 本地到达和核心登记须分别核对。

身份、群组、known、ACK 账本、回退及隔离保护沿用：正式写入人工审核，冲突不覆盖，any 策略不能拼凑多个设备的部分 ACK，隔离至少 30 天，恢复拒绝覆盖，永久删除保持禁用，不清理百度同步目录或云端文件。

## 验证范围

本版通过 29 项安全回归、7 项实际苹果分支 VM 模拟、三平台实际目录保存／重载／失败回滚及导航验证，Android／iOS 模式 Edge 界面检查；检查了移动端、iPad 及 Windows 截图。除目录 helper、设置、导航和明确保存方法外，其余插件实现与 5.2.11 相同（版本文字及换行规范化后比较），样式文件相同。

5.2.11 已有真机证据支持完整 workspace 路径的 main 页面上传原 ACK 后由 Windows 原百度同步目录收到同 SHA 文件。本版据此生成路由，不将模拟导航视为 5.2.12 真机验收。

5.2.12 尚未安装到真机；安卓本版真机回归、Safari 新下载副本的独立 SHA 核验、未登记 ACK 的自动接收尚未验收。百度 App 分享下载提示“文件已移动或删除”的问题不宣称修复。此前原 ZIP 导入、取消、重复去重及重开不弹窗结论继续保留，不要求重复整套操作。
